# Quantum Key Distribution (QKD) Simulator

FastAPI backend + Vite React frontend for simulating QKD protocols (BB84, B92),
attacks on them, ML classification of the attack signatures, secret-key-rate
modeling, and shareable run reports.

**Read the honesty table below before citing any number this app produces.**
Every feature is classified as **real physics simulation** (the actual protocol
math is executed and measured), **real ML (trained + evaluated)** (a model is
actually trained and held-out metrics are reported), or
**conceptual/simplified** (an educational stand-in, not a faithful physical
model). Nothing else is claimed.

---

## Quick start (Docker)

```bash
# 1. Generate a JWT secret and export it (compose refuses to start without it)
export JWT_SECRET=$(python -c "import secrets; print(secrets.token_urlsafe(48))")

# 2. Bring up Postgres + backend
docker compose up --build
```

- Backend: http://localhost:8000 — Swagger docs: http://localhost:8000/docs
- Health: http://localhost:8000/health
- Postgres: localhost:5432 (user/pass/db: `qkd`/`qkd`/`qkd`)
- Frontend is **not** containerized; run it separately (see below):

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

## Run locally without Docker

**Backend** (Python 3.11+):

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # then set JWT_SECRET inside it
uvicorn app.main:app --reload --port 8000
```

Without a database, `/health` reports `"degraded"` — the API still serves
everything except persistence-dependent endpoints. To run just Postgres:
`docker compose up -d db`.

**Frontend** (Node 18+): `cd frontend && npm install && npm run dev` →
http://localhost:5173 (configure the backend URL with `VITE_API_BASE`).

## Required environment variables

| Variable | Service | Required | Purpose |
| --- | --- | --- | --- |
| `JWT_SECRET` | backend | **Yes — no default; the backend refuses to start without it.** When using docker-compose, export it in your shell (or a compose `.env` file); the compose file errors out without it. | Signs the JWT session cookie. Generate: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `DATABASE_URL` | backend | No (default `postgresql+psycopg://qkd:qkd@localhost:5432/qkd`; compose sets it to the `db` service) | SQLAlchemy database URL |
| `OPENAI_API_KEY` | backend | No (empty) | **LLM API key** for AI run summaries. Any OpenAI-compatible chat API works: set `OPENAI_BASE_URL` (default `https://api.openai.com/v1`) and `OPENAI_MODEL` (default `gpt-4o-mini`). Without a key, deterministic rule-based fallback summaries are served and responses are labeled `summary_source: "fallback"`. |
| `VITE_API_BASE` | frontend | No (default `http://localhost:8000`) | Backend base URL used by the browser |
| `IBM token` | — | Per request | The IBM Quantum token for hardware runs is **not** an env var: it is pasted into the Simulate page per submission, kept in memory only, never stored or logged (see `backend/app/hardware.py`). |

Env templates: `backend/.env.example`, `frontend/.env.example`.

## Train the ML model

The classifier artifact (`backend/app/ml/attack_classifier.joblib`) is committed,
so `POST /ml/classify` works out of the box. To retrain:

```bash
cd backend
python -m app.ml.train            # options: --runs-per-class 120 --seed 7
```

## Tests / sanity checks

```bash
cd backend
python scripts/test_bb84.py       # 20 clean-channel BB84 runs; asserts 0 aborts, 0 key mismatches
python scripts/test_attacks.py    # attack sweep; asserts measured QBER scaling, decoy-flagging, etc.
```

## Feature honesty table

**Classifications:**

- **Real physics simulation** — the actual quantum/protocol logic is computed in
  code (Born-rule measurement, Poisson photon statistics, GLLP rate math, or
  execution on real quantum hardware). Simplifications that do not change the
  physics being demonstrated are noted.
- **Real ML (trained + evaluated)** — a model is trained on labeled data
  generated by the real simulator and evaluated on a held-out split with
  reported metrics.
- **Conceptual/simplified** — an educational stand-in. The code is honest about
  what it is; do not present its output as physical simulation.

| Feature | Where | Classification | Notes |
| --- | --- | --- | --- |
| **BB84 protocol pipeline** (encode → channel → measure → sift → QBER → abort → EC → PA) | `backend/app/protocols/bb84.py` | **Real physics simulation** | Born-rule measurement semantics (same basis deterministic, conjugate basis a fair coin); 11% QBER abort threshold; QBER sample discarded. Channel is ideal by default; qubits are simulated state pairs, not wavefunctions. |
| **B92 protocol pipeline** (conclusive-outcome sifting) | `backend/app/protocols/b92.py` | **Real physics simulation** | Two non-orthogonal states; conclusive-outcome sifting rule (~25% yield), not BB84's basis matching. Reuses BB84 EC/PA. |
| **E91 protocol** | `backend/app/protocols/e91.py` | **Conceptual/simplified** | Not implemented — stub raising `NotImplementedError`; module docstring sketches the planned pipeline. Frontend documents it as a "theory preview". |
| **SARG04 protocol** | `backend/app/protocols/sarg04.py` | **Conceptual/simplified** | Not implemented — stub; planned-pipeline docstring only. |
| **COW protocol** | `backend/app/protocols/cow.py` | **Conceptual/simplified** | Not implemented — stub; planned-pipeline docstring only. |
| **Intercept-resend attack** | `backend/app/attacks/intercept_resend.py` | **Real physics simulation** | Eve measures a fraction of qubits in a random basis and re-prepares the measured state; measured sifted-QBER ≈ intensity/4 (BB84) and ≈ intensity/3 (B92), asserted by `scripts/test_attacks.py`. |
| **Photon-number-splitting (PNS) attack + decoy states** | `backend/app/attacks/pns.py` | **Real physics simulation** | Poisson-distributed photon numbers per pulse, 3 decoy intensity levels (1, 1/4, 1/16)·μ, multi-photon siphoning with pulse suppression, detection via intensity-dependent loss spread vs binomial noise floor (3σ flag). |
| **Trojan-horse attack** | `backend/app/attacks/trojan.py` | **Conceptual/simplified** | Deliberately not a physical THA (no optical transfer matrices / isolation ratios / back-reflection models). Modeled as localized error patches at the encoder whose errors cluster spatially — the signature the ML features exploit. The code labels itself a stand-in. |
| **Attack classifier (ML)** | `backend/app/ml/` | **Real ML (trained + evaluated)** | LogisticRegression (StandardScaler pipeline) trained on 480 runs of the *real* BB84/B92 simulators under all attacks at varied intensities (seed 7, 4096 qubits/run). Held-out (25% stratified): accuracy **0.875**, ROC AUC (macro OvR) **0.969**; per-class recall: none 1.00, intercept_resend 0.83, pns 0.97, trojan 0.70. Metrics live in `attack_classifier_meta.json` and are printed at train time — never hardcoded. 16 features across QBER, decoy-loss, gap/timing, and error-clustering families. |
| **ML feature extraction** | `backend/app/ml/feature_extraction.py` | **Real ML (trained + evaluated)** | The features the classifier consumes, computed from actual run results (QBER binomial z, decoy-loss variance/z, detection-gap tail stats, nearest-neighbour error clustering). |
| **`GET /keyrate` — SKR vs distance model** | `backend/app/keyrate.py` | **Real physics simulation** | Textbook GLLP-style asymptotic weak-coherent rate: R = q·[Q₁(1−h₂(e₁)) − Q_μ·f·h₂(E_μ)] with channel transmittance 10^(−αd/10), dark counts, misalignment, μ, EC inefficiency f=1.16, attack-QBER coupling. Pure math, no RNG. Asymptotic — no finite-size effects. |
| **Real hardware execution (IBM Quantum)** | `backend/app/hardware.py`, `routers/hardware.py` | **Real physics simulation** | The *quantum* part is real hardware: actual BB84/B92 circuits (state prep + measurement, 20–50 qubits, ≤4096 shots) submitted via Qiskit Runtime SamplerV2 to real IBM backends; results are per-shot classical registers. The classical sifting replay and result aggregation are conventional code. Requires the user's IBM token per request. |
| **AI run summaries (LLM)** | `backend/app/ai_summary.py` | **Conceptual/simplified** | A convenience narrative layer over completed runs, *not* a simulation of anything. LLM output when `OPENAI_API_KEY` is set (any OpenAI-compatible API); otherwise a deterministic rule-based fallback. Responses label the source (`llm`/`fallback`). |
| **REST simulation API + persistence** | `backend/app/routers/simulate.py`, `models.py` | **Real physics simulation** | Runs the real pipelines, persists every stage (`simulation_runs`, `protocol_stage_logs`); runs are replayable from the DB. The transport/persistence is plumbing; the payloads come from the real simulators. |
| **WebSocket live stage streaming** | `routers/simulate.py` (`/ws/simulate/{protocol}`), `routers/hardware.py` (`/ws/hardware/{job_id}`) | **Real physics simulation** | Streams the real pipeline's stage frames (and real hardware-job status) live; cookie-authenticated. |
| **Key-rate chart UI (frontend)** | `frontend/src/pages/KeyRate.jsx`, `ReportView.jsx` | **Real physics simulation** | Plots the `/keyrate` GLLP curves (and stored report curves) verbatim; axes/log scaling are presentation only. |
| **QBER history chart, stage timeline UI** | `frontend/src/pages/Simulate.jsx` | **Real physics simulation** | Renders measured QBERs and streamed pipeline stages from real runs. |
| **Foundations / protocol theory pages** | `frontend/src/pages/Foundations.jsx`, `Protocols.jsx`, `Comparison.jsx` | **Conceptual/simplified** | Static educational content (SVG diagrams, prose). Correct physics *descriptions*, but no computation. |
| **Reports (share snapshots + PDF)** | `backend/app/routers/reports.py`, `report_pdf.py` | **Real physics simulation** | Snapshots are of real runs (stage logs, ML classification, measured QBER, computed key-rate curves); PDF is a rendering of that snapshot. Snapshotting itself is plumbing, not physics. |
| **Auth (JWT + httpOnly cookie + bcrypt + rate limiting)** | `backend/app/auth.py`, `routers/auth.py` | **Conceptual/simplified** | *(Not a physics claim — classified for completeness.)* Real, standard security engineering: bcrypt hashes, constant-time email-vs-password timing, server-side session revocation, slowapi limits. No quantum content. |
| **Health endpoint / Console dashboard** | `backend/app/routers/health.py`, `frontend/src/pages/Console.jsx` | **Conceptual/simplified** | Infrastructure: DB ping + status display. No physics. |

Rows with no classification are deliberately absent: every feature shipped in
this repo appears in exactly one of the three categories, per its own code
docstrings.

## API overview

| Endpoint | Auth | Description |
| --- | --- | --- |
| `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me` | public / cookie | Register, log in (JWT in httpOnly cookie backed by a `user_sessions` row so logout revokes server-side), log out, whoami. Rate-limited (login 5/min, register 3/min per IP). |
| `POST /simulate/{protocol}` | cookie | Run `bb84` or `b92` once (n_qubits 16–10000, optional noise, attack, seed); returns all stages, ML classification, AI summary. |
| `WS /ws/simulate/{protocol}` | cookie | Same pipeline, streamed stage-by-stage. |
| `GET /simulate/runs` | cookie | Your persisted runs, newest first. |
| `POST /ml/classify` | cookie | Classify a persisted run (`{"run_id": n}`) or a fresh probe run; returns class probabilities + features. 503 if the model artifact is missing. |
| `GET /keyrate` | none | SKR-vs-distance curve + cutoff/peak readouts; all link parameters overridable via query params. |
| `POST /simulate/hardware` | cookie | Submit BB84/B92 to a real IBM Quantum backend (3/min per IP); token in body, never stored. |
| `WS /ws/hardware/{job_id}` | cookie | Stream hardware job status until terminal. |
| `POST /reports/{run_id}` | cookie | Snapshot a run into a public, UUID-keyed report. |
| `GET /reports/{uuid}`, `GET /reports/{uuid}/report.pdf` | none | Read-only report fetch / PDF render. |
| `GET /health` | none | Status + DB check. |

```

  app/
    main.py          FastAPI app, CORS, rate limiting, router registration
    config.py        pydantic-settings (env vars; JWT_SECRET required)
    auth.py          bcrypt, JWT, server-side sessions, slowapi limiter
    models.py        SQLAlchemy models (users, sessions, runs, stages, reports, hw jobs)
    routers/         REST/WS endpoints (auth, simulate, ml, keyrate, hardware, reports, health)
    protocols/       QKD protocol implementations (bb84, b92 runnable; e91/sarg04/cow stubs)
    attacks/         Channel-hook attacks (intercept_resend, pns, trojan)
    ml/              Feature extraction, training script, trained classifier artifact + metadata
    keyrate.py       GLLP secret-key-rate vs distance model
    hardware.py      IBM Quantum submission + polling (token never persisted)
    ai_summary.py    LLM/fallback run summaries
    report_pdf.py    reportlab PDF rendering
  scripts/           test_bb84.py, test_attacks.py sanity sweeps
  requirements.txt, Dockerfile, .env.example
frontend/            Vite + React (JavaScript, plain CSS), pages in src/pages
docker-compose.yml   Postgres + backend
```

## Known limitations

- **E91, SARG04, COW are not implemented** — backend stubs + frontend theory
  pages only. They are never presented as runnable.
- The trojan-horse attack is a conceptual model (see honesty table), as are the
  theory/content pages and AI summaries.
- `docker-compose.yml` starts backend + Postgres only; the frontend runs from
  the dev server.
- Simulations run on an ideal channel with optional per-qubit bit-flip noise;
  there is no fiber loss/decoherence model inside the protocol simulators
  themselves (loss appears in the PNS attack model and in the `/keyrate` link
  model).
- No Alembic migrations yet — schema is created via `create_all()` at startup.
